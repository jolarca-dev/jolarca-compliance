# Policy Exceptions

The only lawful deviation path from policies 01–12.

File naming: `EX-YYYY-NN-<slug>.md`. Every exception must contain:

1. **Policy & requirement** deviated from
2. **Justification** (business/technical)
3. **Compensating controls** in force during the exception window
4. **Risk acceptance**: accountable owner, risk-register ID, accepted score
5. **Expiry date** — mandatory; exceptions without expiry are rejected
6. **DPO sign-off** — mandatory when personal data is in scope

Rules:

- Expired exceptions are policy violations by default; renewal = new file.
- Exceptions are reviewed at each gate and in the annual policy review.
- The exceptions log is append-only; closed exceptions stay visible.
